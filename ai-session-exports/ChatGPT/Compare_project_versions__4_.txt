import { createHash } from "node:crypto";

export function googleEventIdForBooking(bookingId: string): string {
  return createHash("sha256")
    .update(`ledgerwise-calendar:${bookingId}`)
    .digest("hex");
}

The hexadecimal characters are valid within Google's documented base32hex character set.

{

  id: googleEventIdForBooking(bookingId),

    private: {
      ledgerwiseBookingId: bookingId,
    },
  },
}

Specific correctness findings
Timezones and DST — mostly good.
zonedDateTimeToIso() converts a local wall-clock time to a UTC instant, and rejects DST gaps and overlaps rather than silently selecting the wrong instant. buildGoogleEvent() then sends the UTC timestamp plus its IANA timezone.
That is the correct general approach for timed events. I do not see an obvious timezone conversion defect in these files. The remaining uncertainty is real-account behavior, not the basic conversion logic.
Duplicate events and orphan events — a real defect.
The sequence in bookSlot() is:

Create the internal booking using book_slot.
Call syncBookingToGoogle().
Call recordGoogleSync() to save the Google event ID.

If step 2 succeeds and step 3 fails, the internal booking remains, but the database has no google_event_id.
Then:

cancelBooking() skips Google deletion because it only deletes when booking.google_event_id exists.
confirmBooking() may try creating another event if the booking is still pending and has no event ID.
rescheduleBooking() also creates an event if there is no event ID.

A retry can therefore create a duplicate, while cancellation can leave the original event behind.
This is not hypothetical behavior: the current code has no idempotency key, deterministic event ID or reconciliation mechanism.
PATCH 404/410 — confirmed defect.
googleMutation() treats 404 and 410 as success only when method === "DELETE".
For a missing event during rescheduling:

PATCH returns failed.
recordGoogleSync() receives a failed result.
The existing event ID is preserved because the RPC only replaces it when a new non-null ID is supplied.
Future reschedule attempts keep trying to patch the same missing event.

That needs a recovery path.
Security and event content — needs attention.
The actual event content is more revealing than the documentation suggests:

summary: Ledgerwise call: Jane Doe
description: prospect name, prospect email, company UUID and a Ledgerwise note.

No prices or pricing promises are sent. No attendee list is sent, so the current code does not invite the prospect or send them an invitation.
However, the prospect's name and email are sent to Google's Calendar API and stored in the external calendar. docs/SECURITY.md says Google Calendar is optional and that credentials belong in environment variables, but it does not explicitly describe this transfer of prospect data.
I recommend changing the event to something like:
{
  summary: "Ledgerwise sales call",
  description: `Internal booking reference: ${bookingId}`,
}

If the sales team needs a human-readable identifier, use the company name only after deciding that this disclosure is acceptable. The email address is not necessary for event synchronization.
The token handling is comparatively restrained:

google.ts reads credentials from server-side environment variables.
It does not send credentials to the browser.
It does not log access tokens or refresh tokens.
It reports HTTP status codes rather than printing the raw Google response body.
recordGoogleSync() logs a Supabase error message, but not the Google credentials.

The main security concern is therefore the data included in the event, plus the fact that the refresh token is a long-lived secret held in environment configuration.
Google OAuth scope: is calendar.events enough?
Yes, for the current implementation
The current integration only needs to create, update and delete events. Google lists https://www.googleapis.com/auth/calendar.events as an accepted scope for all three relevant event operations. It does not need the much broader calendar scope. 
For the current integration, request:
https://www.googleapis.com/auth/calendar.events

If you later add availability checks, request an additional FreeBusy scope rather than broadening to full calendar access without a reason.

Important: the seven-day refresh-token issue
Your suspicion is correct, with an important qualification.
Google states that an OAuth application configured as External and left in Testing issues refresh tokens that expire after seven days when the requested scopes go beyond basic profile information. calendar.events is beyond those basic profile scopes, so this limitation applies. 
That means an external Testing app is unsuitable for unattended long-term synchronization.
For Ledgerwise:

If you have Workspace, prefer an Internal app.
If you use a personal Gmail account, do not assume Testing will provide a permanent token.
For an External app, investigate publishing to Production and the applicable OAuth verification requirements.
A service account with a shared calendar avoids the user refresh-token lifecycle altogether, but changes the calendar ownership and sharing arrangement.

Even production refresh tokens can be revoked or expire under other conditions, so the application still needs to handle reauthorization.

Priority 2 — Add deterministic event IDs
Blocking
File: lib/calendar/google.ts
The current POST has no stable identifier, so every retry can create another event.
Google permits the client to specify an event ID when inserting an event, subject to its ID format requirements. A stable ID can therefore make retries recoverable. 
I recommend deriving a deterministic ID from the internal booking UUID:
import { createHash } from "node:crypto";

export function googleEventIdForBooking(bookingId: string): string {
  return createHash("sha256")
    .update(`ledgerwise-calendar:${bookingId}`)
    .digest("hex");
}

The hexadecimal characters are valid within Google's documented base32hex character set.
Change syncBookingToGoogle() so the POST body includes:
{
  ...buildGoogleEvent(input),
  id: googleEventIdForBooking(bookingId),
  extendedProperties: {
    private: {
      ledgerwiseBookingId: bookingId,
    },
  },
}

This requires adding bookingId to the event input.
On a 409 Conflict, do not blindly report failure or create a different ID. Fetch the event using the deterministic ID, check its private booking reference, and treat it as the already-created event if it belongs to that booking.
This addresses the case where Google created the event but the response was lost or the database update failed.
Tests:

Two create attempts for the same booking must result in one event.
A simulated lost response followed by retry must recover the existing event.
A conflicting ID belonging to another booking must not be accepted.

This is the most important production reliability improvement.
The present recordGoogleSync() only logs a metadata-write failure. It has no recovery mechanism.
I recommend adding a small synchronization job/outbox table with:

booking_id
operation (create, update, delete)
status (pending, processing, synced, failed)
attempt_count
last_error
next_attempt_at
created_at
updated_at

The internal booking mutation and outbox record should be written in the same database transaction.
Then a worker processes the outbox:

Reads pending work.
Calls Google.
Saves the event ID and sync status.
Marks the job complete.
Retries failures with backoff.

The Google API must remain outside the database transaction. Do not hold a database lock open while waiting for Google.
This preserves your rule: the internal booking is authoritative, and Google failures never roll it back.
For the prototype, a manually triggered retry action is a smaller first step. For production reliability, use the outbox.

Proposed first-time verification script
This is the small script I would add before enabling the two flags. It uses the existing token helper but deliberately bypasses the sync-enabled check, so it can verify the real Google account without falsely marking the integration verified.
Create scripts/verify-google-calendar.mjs:
import { loadEnvConfig } from "@next/env";
import { randomUUID } from "node:crypto";

loadEnvConfig(process.cwd());

const required = [
  "GOOGLE_CLIENT_ID",
  "GOOGLE_CLIENT_SECRET",
  "GOOGLE_REFRESH_TOKEN",
  "GOOGLE_CALENDAR_ID",
];

for (const key of required) {
  if (!process.env[key]) {
    throw new Error(`Missing environment variable: ${key}`);
  }
}

async function main() {
  const tokenResponse = await fetch("https://oauth2.googleapis.com/token", {
    method: "POST",
    headers: {
      "Content-Type": "application/x-www-form-urlencoded",
    },
    body: new URLSearchParams({
      client_id: process.env.GOOGLE_CLIENT_ID,
      client_secret: process.env.GOOGLE_CLIENT_SECRET,
      refresh_token: process.env.GOOGLE_REFRESH_TOKEN,
      grant_type: "refresh_token",
    }),
  });

  if (!tokenResponse.ok) {
    throw new Error(`Token exchange failed: HTTP ${tokenResponse.status}`);
  }

  const { access_token } = await tokenResponse.json();

  if (!access_token) {
    throw new Error("Google returned no access token.");
  }

  const calendarId = encodeURIComponent(
    process.env.GOOGLE_CALENDAR_ID
  );

  const baseUrl =
    `https://www.googleapis.com/calendar/v3/calendars/${calendarId}/events`;

  const headers = {
    Authorization: `Bearer ${access_token}`,
    "Content-Type": "application/json",
  };

  const eventId = randomUUID().replaceAll("-", "").toLowerCase();

  const now = Date.now();
  const start = new Date(now + 10 * 60_000);
  const end = new Date(now + 40 * 60_000);

  const event = {
    id: eventId,
    summary: "Ledgerwise Google Calendar verification",
    description: "Temporary integration test. Safe to delete.",
    start: {
      dateTime: start.toISOString(),
      timeZone: "UTC",
    },
    end: {
      dateTime: end.toISOString(),
      timeZone: "UTC",
    },
  };

  let created = false;

  try {
    const createResponse = await fetch(baseUrl, {
      method: "POST",
      headers,
      body: JSON.stringify(event),
    });

    if (!createResponse.ok) {
      throw new Error(`Event creation failed: HTTP ${createResponse.status}`);
    }

    const createdEvent = await createResponse.json();
    created = true;

    console.log("PASS: Event created.");

    const updateResponse = await fetch(
      `${baseUrl}/${encodeURIComponent(createdEvent.id)}`,
      {
        method: "PATCH",
        headers,
        body: JSON.stringify({
          summary: "Ledgerwise Google Calendar verification — updated",
        }),
      }
    );

    if (!updateResponse.ok) {
      throw new Error(`Event update failed: HTTP ${updateResponse.status}`);
    }

    console.log("PASS: Event updated.");

    const deleteResponse = await fetch(
      `${baseUrl}/${encodeURIComponent(createdEvent.id)}`,
      {
        method: "DELETE",
        headers,
      }
    );

    if (!deleteResponse.ok && deleteResponse.status !== 404 &&
        deleteResponse.status !== 410) {
      throw new Error(`Event deletion failed: HTTP ${deleteResponse.status}`);
    }

    created = false;
    console.log("PASS: Event deleted.");
    console.log("Google Calendar create/update/delete verification succeeded.");
  } finally {
    // Clean up if update or another step failed after creation.
    if (created) {
      await fetch(`${baseUrl}/${encodeURIComponent(eventId)}`, {
        method: "DELETE",
        headers,
      }).catch(() => {});
    }
  }
}

main().catch((error) => {
  console.error(error.message);
  process.exitCode = 1;
});

Run it from the project root:
node scripts/verify-google-calendar.mjs

The generated event ID uses lowercase hexadecimal characters, which satisfy Google's permitted event ID character set. 
This is a first-pass verification script, not a replacement for the application's eventual OAuth connection flow or its automated integration tests.

async function main() {
  const tokenResponse = await fetch("https://oauth2.googleapis.com/token", {
    method: "POST",
    headers: {
      "Content-Type": "application/x-www-form-urlencoded",
    },
    body: new URLSearchParams({
      client_id: process.env.GOOGLE_CLIENT_ID,
      client_secret: process.env.GOOGLE_CLIENT_SECRET,
      refresh_token: process.env.GOOGLE_REFRESH_TOKEN,
      grant_type: "refresh_token",
    }),
  });

  if (!tokenResponse.ok) {
    throw new Error(`Token exchange failed: HTTP ${tokenResponse.status}`);
  }

  const { access_token } = await tokenResponse.json();

  if (!access_token) {
    throw new Error("Google returned no access token.");
  }

  const calendarId = encodeURIComponent(
    process.env.GOOGLE_CALENDAR_ID
  );

  const baseUrl =
    `https://www.googleapis.com/calendar/v3/calendars/${calendarId}/events`;

  const headers = {
    Authorization: `Bearer ${access_token}`,
    "Content-Type": "application/json",
  };

  const eventId = randomUUID().replaceAll("-", "").toLowerCase();

  const now = Date.now();
  const start = new Date(now + 10 * 60_000);
  const end = new Date(now + 40 * 60_000);

  const event = {
    id: eventId,
    summary: "Ledgerwise Google Calendar verification",
    description: "Temporary integration test. Safe to delete.",
    start: {
      dateTime: start.toISOString(),
      timeZone: "UTC",
    },
    end: {
      dateTime: end.toISOString(),
      timeZone: "UTC",
    },
  };

  let created = false;

  try {
    const createResponse = await fetch(baseUrl, {
      method: "POST",
      headers,
      body: JSON.stringify(event),
    });

    if (!createResponse.ok) {
      throw new Error(`Event creation failed: HTTP ${createResponse.status}`);
    }

    const createdEvent = await createResponse.json();
    created = true;

    console.log("PASS: Event created.");

    const updateResponse = await fetch(
      `${baseUrl}/${encodeURIComponent(createdEvent.id)}`,
      {
        method: "PATCH",
        headers,
        body: JSON.stringify({
          summary: "Ledgerwise Google Calendar verification — updated",
        }),
      }
    );

    if (!updateResponse.ok) {
      throw new Error(`Event update failed: HTTP ${updateResponse.status}`);
    }

    console.log("PASS: Event updated.");

    const deleteResponse = await fetch(
      `${baseUrl}/${encodeURIComponent(createdEvent.id)}`,
      {
        method: "DELETE",
        headers,
      }
    );

    if (!deleteResponse.ok && deleteResponse.status !== 404 &&

    created = false;

  } finally {

        method: "DELETE",
        headers,
      }).catch(() => {});
    }
  }
}
