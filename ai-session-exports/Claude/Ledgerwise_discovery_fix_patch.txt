It keeps product and collection links as candidates and drops blog and listicle links.

For drafting emails, how does Groq work ?


Claude:
I only read the shared AI layer, not the email code itself, so I'll look before answering.
Groq isn't the whole story for emails. It's one step in a short safety chain, and it's the only AI step in it.
What happens when you click "generate draft"

Safety checks come first, before any AI. The app refuses to start unless the company has a usable contact email, the email isn't on the suppression list, and the contact's source has been human-verified in the review queue.
It selects the facts the AI is allowed to use. Only human-verified sources, at most 6, are passed in as JSON: the claim, the evidence quote, and the source link.
It calls Groq, which writes the email. Groq is the only model used for emails, because the code deliberately excludes Gemini for messages. The reason in the code comments is that Gemini's free tier may train on what you send, and these messages contain prospect details.
Model: openai/gpt-oss-120b unless you set GROQ_MODEL.
Settings: temperature 0.3 (fairly consistent wording), maximum 700 output tokens.
The prompt tells it to use only the supplied facts, mention no pricing, say it's an AI assistant, keep the body under 140 words, and return JSON with a subject and body.


Plain code checks what Groq wrote. It rejects the draft if it has an unfilled placeholder like {{name}} or [insert company]. Separate text patterns block pricing words, guarantees, claims of being human, and pressure language like "act now".
If Groq is down, rate-limited, or the draft fails a check, it falls back to a fixed template. The template is built from the verified facts. It's marked template in the record, so you can tell it wasn't AI-written. If even the template fails the checks, no draft is created.
Nothing is sent automatically. The draft is saved for a human to review and edit, and sending is a separate step.

The point of this design
The AI is trusted to write well but not to be safe. Anything risky is blocked by ordinary code that doesn't depend on the AI behaving. The reply-drafting feature for prospect responses (lib/conversations/reply.ts) uses the same pattern.
I read this code now, but I didn't change or test any of it, so what I've described is the code as written, not something I observed running.
